## 2. 新增保护

### Landing v2 交接

- 正式计划、输入哈希、创建时间和过期时间完整保存。
- 缺少交接信封时返回 `missing`，不修改存储。
- 读取成功不会自动清除；只有调用方确认持久化成功后才能清除。
- 过期、版本不支持、JSON 损坏、正式计划无效和空哈希均被拒绝。

### 工作台启动

启动优先级已抽为可单测纯决策：

```text
有效 v2 handoff
  → 有效 v1 handoff
  → IndexedDB 当前计划
  → localStorage 旧草稿
  → 空状态
```

新增回归覆盖：

- v2 优先于 v1 和已有计划。
- v1 优先于已有计划。
- 已有计划优先于旧草稿。
- 过期 v2 不会挡住已有计划。
- 无法解析的旧值会被跳过。
- 启动决策本身不清除临时数据。

### 固定分析场景

新增三个固定、可复现、无随机时间的正式 `LifePlan`：

1. 个人基线：只有 `self`，0 元起始资金，退休前后支出边界连续。
2. 购房与孩子重叠：孩子支出在购房后 6 个月开始，用于后续重叠规则。
3. 流动性缺口：存在可用资金为负、净资产仍为正的月份。

每个 fixture 均通过 P0 校验，并验证两次 P1 计算的输入哈希、摘要和年度结果一致。
