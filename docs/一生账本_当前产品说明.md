## 一、产品概述

### 1. 产品定位

一生账本是一款面向个人和家庭的长期现金流规划工具。它不是逐笔记账软件，也不提供投资建议，而是把当前可用资产、收入、支出以及职业、家人、孩子、住房、父母和退休等人生安排，转换为按月计算、按年展示的长期资金计划。

产品主要回答四个问题：

1. 按照当前输入，规划期内是否会出现可用资金缺口。
2. 首次缺口发生在什么时候，最低可用资金是多少。
3. 退休、购房、育儿等安排如何改变长期资金轨迹。
4. 调整时间、金额或退休计划后，结果会怎样变化。

所有结论均是基于当前输入和明确假设的情景计算，不是未来预测或收益保证。

### 2. 目标用户

产品适用于希望自行梳理长期收支的个人与家庭，尤其是需要同时考虑职业变化、家庭责任、住房和退休安排，但不希望使用复杂专业模型的用户。

用户不需要一次填完所有信息。产品先用少量数据建立个人基线，再允许按人生阶段逐步补充；未涉及的阶段可以跳过或标记为当前不考虑。

### 3. 当前范围

当前正式产品支持：

- 人民币计价。
- 按今天购买力进行计算和展示。
- 当前浏览器内的一份活动计划。
- 本地计算、本地保存、JSON 备份与恢复。
- 中文和英文界面、浅色和深色主题。
- 首页、规划工作台和生产环境离线应用壳。

当前正式产品不包含：

- 账户、云同步、多设备同步或多人协作。
- 自动获取房价、政策、养老金或城市生活成本。
- 完整个税计算、保险测算或投资组合建议。
- 由 AI 生成财务结果、修改正式计划或给出生活建议。
- 对未来收入、资产收益、房价或养老金作保证。

## 二、产品与交互设计

### 1. 整体信息架构

产品由两个主要界面组成：

1. **首页个人基线**：用七项输入快速建立最小可计算计划。
2. **正式规划工作台**：包含“概览”“规划”“年度账本”三个视图。

用户路径为：

```text
填写个人基线 → 查看基线结果 → 加入人生大事
→ 补充或修改正式计划 → 查看长期结果与重点
→ 试算不同安排 → 在年度账本中核对
```

首页向工作台交接时，金额和家庭数据不会写入网址。工作台读取成功后，将计划保存在当前浏览器。

### 2. 首页个人基线

首页首屏由产品说明和个人基线计算器组成。计算器默认值为：

| 输入             |       默认值 |
| ---------------- | -----------: |
| 当前年龄         |        30 岁 |
| 计划退休         |        60 岁 |
| 计算到           |        90 岁 |
| 起始可用资产     |       0 万元 |
| 个人每月到手     | 20,000 元/月 |
| 工作期个人月支出 | 10,000 元/月 |
| 退休后每月需自付 |  5,000 元/月 |

年龄必须满足“当前年龄 < 退休年龄 < 计算终点”。金额输入可在“元”和“万”之间切换，单位切换只改变填写方式，不改变实际金额。

提交后，页面在原位置展示：

- 当前输入下的结论：全程无缺口、出现并持续缺口，或中途缺口后恢复。
- 首次资金缺口的年龄和月份。
- 计算终点可用资金。
- 当前时间范围和计算口径。

如果用户在计算后又修改输入，进入正式计划的按钮会暂时禁用，直到重新计算，避免把旧结果与新输入一起带入工作台。

首页下方使用“三步使用方式、核心能力、常见问题和行动入口”解释产品。文案明确说明产品不是记账软件、结果不是 AI 计算、计算不是未来预测、快速计算不上传个人数据。

### 3. 工作台全局结构

工作台顶部固定显示：

- 产品入口和当前计划名称。
- 自动保存状态。
- 计算依据入口。
- 浅色／深色主题切换。
- 中文／英文切换。
- 重命名、导出、导入、恢复快照和删除重建。

桌面端在顶部使用“概览／规划／年度账本”标签；移动端使用固定底部导航。标签支持方向键、Home 和 End 键切换。

产品区分以下状态：读取中、空计划、读取失败、计算中、计算失败、保存中、已保存、保存失败和跨标签页冲突。输入或计算失败时保留上一份有效结果，不用不完整数据覆盖正式结果。

### 4. 概览

概览用于先给结论，再提供依据。内容依次包括：

#### 4.1 结果摘要

- 当前规划是否可持续。
- 规划终点可用资金。
- 首次资金缺口。
- 最低可用资金。
- “修改计划”入口。

结论始终使用条件式表述，并注明按今天购买力估算、不是未来保证。

#### 4.2 人生时间轴

主轴只展示少量关键节点，并按实际月份排序。当前会优先展示购房、孩子或家人的一次性事件、其他一次性人生大事和退休，最多五项。持续性的月度收支、普通支出分类和房贷结束不会挤入主轴。

“查看全部时间节点”中保留完整事件列表，包括持续项目的起止时间和房贷最后一期。点击节点可进入对应规划模块。

#### 4.3 人生安排完成状态

以紧凑入口展示“现在、职业发展、家人、孩子、住房、父母、退休”。每项显示已计入、暂未计入或当前不考虑，并可直接进入相应编辑区。

#### 4.4 可用资金与净资产

主图以年龄为横轴、年末金额为纵轴：

- 可用资金使用实线和浅面积展示。
- 零线以上使用克制的绿色，零线以下使用琥珀色表示资金缺口。
- 标出退休年份、首次缺口、退休年末余额和计算终点余额。
- 净资产与可用资金不同时，可开启虚线对照；两者重合时只显示一条线。
- 图下单独说明月度最低可用资金，因为它可能低于图中展示的年末余额。

图表附带可展开的数据表，便于读取精确数值和使用辅助技术。

#### 4.5 年度支出与收支比较

同一图表区域可切换两种视图：

- “每年花多少”：按日常生活、住房与贷款、孩子、父母、其他、退休进行年度堆叠。
- “收入与支出”：收入使用面积线，支出使用柱形，二者共用同一金额刻度，柱线高度可以直接比较。

两种视图都使用同一份年度账本数据，不额外生成一套结果，并提供可展开的精确数据表。

#### 4.6 按人生阶段看

关键人生事件将整个规划期分成多个阶段。每个阶段展示：

- 年龄范围和持续年数。
- 支出构成比例。
- 主要支出类别。
- 月均、年均和阶段合计。

退休前的阶段统一称为“职业与过渡期”，其中可以同时包含正常工作、换工作和暂停工作的月份；退休后的阶段称为“退休生活期”。

#### 4.7 投资本金与收益区间

概览提供一个独立的投资情景图：

- 深色实线是完全不计算投资收益的本金计划。
- 淡绿色铺色是用户设置的潜在收益区间。
- 淡橙色铺色是用户设置的潜在亏损区间。

投资区间只用于观察不确定性，不进入首次缺口、最低资金、资金可持续年龄、年度快照、净资产或 Agent 正式结论。没有投资安排时只显示本金计划线。

#### 4.8 计划中的重点与试算

系统最多展示三条重点，来源是固定规则而不是 AI。规则覆盖：

- 住房支出与首次缺口接近。
- 住房与孩子支出时间重叠。
- 可用资金为负但净资产为正。
- 退休初期出现缺口。
- 退休支出对长期结果影响较大。
- 可用资金实际收益率为零。
- 部分支出仍按总额估算。
- 已填写阶段下暂未出现缺口。

每条重点都能返回相关输入。住房与缺口的因果说明只有在移除该住房支出后首次缺口确实延后或消失时才会显示。

系统可提供最多三个试算入口，候选来自四类受控修改：调整住房支出时间、调整退休自付预算、调整退休时间、调整起始可用资产。试算只修改计划副本，先展示首次缺口、最低可用资金和终点可用资金的前后差异；用户明确应用后才写入正式计划，并可撤销一次。正式计划发生变化或其他标签页更新后，旧试算会失效。

### 5. 规划

规划页采用“人生阶段导航 + 单一编辑区”，不在一个页面同时展开全部表单。

桌面端使用左侧阶段导航，移动端使用原生下拉选择。页面顶部保留人生时间轴，便于从事件直接进入对应模块。未提交的表单在切换模块、返回首页、切换语言或使用浏览器前进后退时会提示是否放弃。

#### 5.1 现在

“现在”包含四个子项：

- 目前资产：编辑现有可用资产与非流动资产，查看已记录债务，并可增加可用资产。
- 收入与工作：编辑当前月收入。
- 日常生活：编辑当前月总支出，并可从总额中拆分分类。
- 基本信息：编辑当前年龄、退休年龄和规划终点。

可用资产进入现金滚动；房产等非流动资产只进入净资产，不自动用于弥补现金缺口。

#### 5.2 职业发展

职业发展包含四种安排：

- 每年涨薪：设置当前工资的年均实际涨幅及生效区间；提供 0%、1%、3% 快捷值，0% 标注“购买力不变”。区间结束后工资保持当时水平。
- 换工作：在指定期间用新工资替换原工资，并可单独设置新工作的实际涨幅。
- 副业：作为独立净收入与工资相加，可设置自己的持续时间。
- 暂停工作：指定期间工资为零，副业保留，结束后恢复原工资轨迹。

相同类型的工资覆盖区间不能冲突。职业涨幅是扣除通胀后的实际变化，不是名义加薪比例。

#### 5.3 家人、孩子、父母与其他人生事件

这些模块使用统一的多项目编辑方式：

- 可以保存多个独立项目。
- 项目名称先从参考下拉中选择，也可以自定义或修改名称。
- 可设置收入或支出方向、每月／每年／一次性频率、金额、开始月份和结束月份。
- 金额可在“元”和“万”之间切换。
- 可以逐项修改、移除，或一键清空当前页面的全部项目。

各模块提供的参考名称为：

- 家人：家人支持、共同生活、婚礼。
- 孩子：出生准备、日常养育、教育学费、二胎准备。
- 父母：父母支持、日常赡养、医疗照护。
- 其他人生事件：旅行、进修、购车、收到赠与、临时医疗支出、紧急维修、一次性奖金。

孩子项目固定为支出；家人和父母允许双向记录资金支持。参考名称只用于快速填写，不限制用户自主命名。

#### 5.4 住房

住房包含“租住与收租”“购房”和“换城市生活”三个子项。

租住与收租使用通用多项目表单，可记录租房、收租和装修，也可以自定义名称。

购房支持多套安排。每套可填写：

- 项目名称和购房月份。
- 房价。
- 全款或“首付 + 贷款”。
- 首付、贷款年利率和贷款年限。

表单实时预览贷款金额、预计月供和全期利息，并展示购房前可用资金、扣除首付、首月月供和购房当月结束余额。首付从已有可用现金中扣除；房产和贷款从购房月份进入净资产；贷款不会作为可用收入。当前贷款方式为等额本息，最后一期按剩余本息结清。税费、装修、维修和租金需要另建项目。

换城市生活支持多项安排。每项可填写当前城市、目标城市、搬迁月份、一次性搬迁费，以及搬迁后的每月住房、生活和收入变化。正数表示相应项目增加，负数表示减少，0 表示不变；系统只采用用户明确确认的金额，不会依据城市名称自动推算房价、工资或生活成本。只填写城市和日期时不会改变正式计算。确认后的金额复用现有现金流模型，人生时间轴和长期趋势会显示搬迁节点，点击节点可返回对应安排。

#### 5.5 退休

退休模块分别填写：

- 退休后每月支出。
- 每月养老金及其他稳定收入。

退休支出填写完整生活支出，不要求先扣除养老金；养老金作为独立收入从退休月份开始计入。系统不会自动预测养老金，不确定时可以填写 0。

#### 5.6 高级假设

高级假设只包含：

- 资金缺口实际年成本。

正式计划对正余额和资产始终按本金计算；负余额可按用户填写的实际年成本计算。投资收益与亏损只在独立投资区间图中展示，不代表保证。

#### 5.7 投资

投资模块支持建立多个安排，每项填写名称、本金、波动档位、年化下限、年化上限和起止月份。低波动、中波动和高波动只是可编辑的输入模板；用户修改边界后显示为自定义。

投资本金在投资开始月从可用资金中预留，持有期间不再用于日常开支，并在结束时转回；不会在设置当下重复扣减现金。保存时会按投资开始月份校验当时预计可用资金，避免同月投资安排的本金合计超过可用额度。收益上下限不写入正式账本，只用于分析页的铺色区间。

#### 5.8 总额与明细

日常支出以及孩子、住房、父母等分类可以从已有月支出总额中拆分。拆分只是改变分类，不重复增加支出：

- 明细不足总额时，差额保留为“待分类”。
- 明细等于总额时，全部由明细替代。
- 明细超过原总额时，必须确认将明细合计作为新的总额。

额外人生项目只用于记录尚未包含在当前收入或支出中的金额。

### 6. 年度账本

年度账本由同一份月度结果汇总。默认只显示起点、终点、退休、首次缺口、最低余额以及人生事件涉及的关键年份，也可以切换为全部年份。

桌面端以表格展示年份／年龄、阶段、收入、支出、年末可用资金、债务和净资产，并以低饱和度条形辅助比较量级。移动端使用紧凑年度卡片，保留年末资金和收入／支出比例。

点击某一年会打开详情抽屉，展示该年各项结果、支出分类，以及该年度规划范围内逐月的收入、支出和月末可用资金。存在缺口时可以直接定位首次缺口年份。

### 7. 视觉设计

产品采用工具型、低干扰的视觉体系：

- 中性浅灰背景和白色内容面，深色主题使用深蓝灰背景。
- 绿色用于主操作、选中状态和正向资金；琥珀色用于缺口、风险和需要确认的内容；红色只用于明确错误或负数。
- 图表颜色降低饱和度，类别颜色保持一致，不使用高亮霓虹色。
- 正文字体为 Noto Sans 与系统无衬线回退；金额使用等宽数字对齐。
- 内容宽度最大 1280px，工作区正文最大约 1152px；卡片使用细边框、8–12px 圆角和克制阴影。
- 主要表单控件最小高度为 44px；移动端输入文字至少 16px，避免聚焦缩放。
- 图表不依赖动画表达结果，并为精确数据提供表格替代。

### 8. 响应式与无障碍

当前界面覆盖手机、平板和桌面布局：

- 首页双栏在窄屏变为纵向布局。
- 规划页桌面显示阶段侧栏，移动端改为下拉选择。
- 工作台桌面使用顶部标签，移动端使用底部导航并适配安全区。
- 表格在移动端改为卡片或允许局部横向滚动，不让整页产生横向溢出。

已实现的无障碍措施包括：语义化标题和地标、标签页键盘操作、可见焦点、44px 触控目标、错误提示与状态播报、抽屉焦点管理、图表表格替代、减少动态效果偏好支持、浅色和深色主题对比度检查。

当前自动化检查不等同于真实 VoiceOver／NVDA、物理手机或完整 WCAG 认证。

## 三、技术实现

### 1. 技术栈

正式产品基于以下技术实现：

- Next.js 16.0.7 App Router。
- React 19.2.1 与 TypeScript 5。
- Tailwind CSS 4 负责布局和视觉样式。
- next-intl 4.3.4 负责中英文文案与路由语言。
- Recharts 2.15.4 负责资金、支出、收支和情景图表。
- Lucide React 负责功能图标。
- IndexedDB、Web Crypto、BroadcastChannel、sessionStorage 和 Service Worker 负责本地数据、完整性、标签页协调、临时交接和离线应用壳。

正式计算、分析、试算和图表数据均在浏览器本地执行，不依赖服务器 API 或 AI 服务。

### 2. 分层结构

一生账本代码位于 `src/features/life-ledger/`，主要分为：

- `domain/`：计划数据类型、金额／月份／比例基础类型、校验、迁移和总额解析。
- `calculation/`：确定性月度计算、年度汇总、所需收入和影响度计算。
- `landing/`：个人基线输入、校验、结果和工作台交接。
- `workspace/plan/`：阶段导航、表单、事件、职业和购房编辑。
- `workspace/overview/`：概览、时间轴、图表、阶段支出、规则重点和情景对照。
- `workspace/ledger/`：年度账本和月度详情。
- `analysis/`：展示数据派生、固定规则分析、行动候选和副本试算。
- `storage/`：IndexedDB 仓储、备份、快照和临时交接。
- `offline/` 与 `scripts/offline/`：生产环境离线应用壳。

页面层只负责输入、状态和展示；正式金额结果只能由同一套确定性计算内核生成。

### 3. 正式数据模型

正式计划使用 `LifePlan 2.0.0`。核心数据包括：

- 计划起始月、退休月和结束月。
- 自己、家人、孩子、父母等成员。
- 收入与支出总额桶、分类明细和独立事件。
- 可用资产、存款、投资、房产及其他资产。
- 房贷、消费贷及其他负债。
- 投资本金、展示用收益区间和资金缺口成本。
- 数据来源、确认状态、版本和更新时间。

底层使用三种明确单位：

- 金额：整数分 `MoneyCents`，避免长期浮点累计误差。
- 时间：整数月份 `MonthIndex`，格式为 `年份 × 12 + 月份偏移`。
- 比例：整数基点 `BasisPoints`，100 基点等于 1%。

所有收支项目都带有方向、分类、归属成员、金额、频率、起止月份、实际增长率、来源和确认状态。频率支持每月、每年指定月份和一次性指定月份。

### 4. 总额解析与防重复计算

收入和支出桶支持 `summary` 与 `detailed` 两种模式。解析时只允许一种表示进入计算：

- `summary` 模式只使用总额。
- `detailed` 模式排除总额，使用明细。
- 明细低于原总额时，自动生成“待分类”差额。
- 明细高于原总额时，只有用户确认新的明细合计后才通过校验。

解析过程生成可追溯记录，保存包含哪些输入、排除了哪个总额以及是否生成待分类项。

### 5. 月度计算内核

当前计算版本为 `2.2.0`，规则版本为 `monthly-cashflow-housing-2026-10`。

计算从计划起始月逐月运行到结束月之前，单月顺序为：

1. 读取月初可用资金。
2. 正余额保持本金；对负余额应用资金缺口成本。
3. 根据频率、时间和增长区间计入当月收入与支出。
4. 处理工资替换、副业叠加和暂停工作。
5. 计提债务利息和还款。
6. 非流动资产保持本金价值。
7. 得出月末可用资金、非流动资产、债务和净资产。

关键公式口径：

```text
当月净现金流 = 当月收入 - 当月支出
月末可用资金 = 月初可用资金 + 资金缺口成本 + 当月净现金流
净资产 = 月末可用资金 + 非流动资产 - 债务余额
```

实际年增长率转换为等效月度复利率。工资增长只在指定区间内复利，区间结束后保持当时金额。投资区间函数可以按用户设置的上下限计算展示差额，但不会把差额写回正式月度结果。

换工作通过 `replace-salary` 明确替换本人基础工资；暂停工作使用零金额工资替换，因此不会误删副业。退休后基础工资停止，但独立设置的副业、养老金或其他收入可以继续发生。

房贷使用名义月利率“年利率 ÷ 12”，每月还款不超过剩余本息，最后一期结清。未来购房在购房月同时计入首付支出、房产和贷款本金；贷款本金不作为现金收入。

### 6. 计算结果

月度结果包含：

- 月初和月末可用资金。
- 收入、支出、余额收益和净现金流。
- 非流动资产、债务余额和净资产。
- 收入与支出的分类合计。
- 当月使用的计算记录 ID。

年度结果严格由月度结果汇总，包含全年收入、支出、收益、年末可用资金、年内最低资金、年末非流动资产、债务、净资产及分类合计。

摘要结果包含：

- 是否曾出现缺口。
- 首次缺口月份和年份。
- 全期最低可用资金。
- 终点、退休时可用资金。
- 终点债务和净资产。
- 使终点不为负、以及使全程不出现缺口所需的月收入。
- 金额增加 10% 后对终点余额影响最大的三项输入。

所需收入通过对工作期月收入补充额进行确定性二分求解。影响度通过单独扰动每项输入并重新计算得出。当前主界面只展示与当前任务相关的摘要、图表和重点，不把全部内核结果同时铺在页面上。

### 7. 校验与错误处理

正式计算前会校验：

- 数据结构版本。
- 金额是否为安全整数分且不为负。
- 起止月份和退休月份是否合法。
- 成员引用、输入来源和 ID 是否完整且不重复。
- 实际增长率和收益率是否合法。
- 每年发生月份是否合法。
- 总额与明细是否已经确认。
- 待确认的辅助数据是否已确认。
- 职业工资覆盖区间是否冲突。

校验失败时，安全计算接口返回结构化错误，不返回部分账本。工作台保留上一份有效结果，提示用户检查输入。

### 8. 派生分析与图表

图表、人生时间轴、阶段支出和关键年份都从正式月度或年度结果派生，不保存第二份现金流结果。

固定规则分析版本为 `1.1.0`。系统按“缺口、关注、信息”的顺序排序，去除指向同一模块的重复项，最多展示三条。分析模块不调用网络、浏览器存储或 AI。

投资情景图以正式年度本金结果为基线，叠加独立的上下行情景差额；开始前没有区间，结束后停止复利并冻结差额。正式试算仍使用计划副本和同一计算器；未应用的试算不改变计划 revision，也不会保存。

### 9. 工作台状态与自动保存

工作台使用 React reducer 管理计划、结果、保存状态、计算状态、结果差异、试算快照和外部冲突。

用户确认编辑后会：

1. 更新计划的 `updatedAt`。
2. 将结果标记为待更新。
3. 重新运行安全月度计算。
4. 计算成功后更新结果并比较修改前后差异。
5. 通过串行保存队列写入 IndexedDB。

当前实现对计算使用约 400ms 延迟，对自动保存使用约 500ms 延迟，减少连续输入造成的重复工作。保存队列按顺序执行，避免旧修改在新修改之后落盘。

跨标签页通过 `BroadcastChannel` 通知。保存时使用预期 revision 做乐观并发检查；发现其他标签页已经更新时，旧页面不会覆盖新记录，并要求用户读取最新版本。

### 10. 本地存储、备份与恢复

正式计划保存在 IndexedDB 数据库 `life-ledger`。数据库包含：

- `plans`：当前正式计划。
- `snapshots`：历史快照，每份计划保留最近 10 个 revision。
- `resultCache`：结果缓存空间。
- `meta`：当前活动计划等元数据。

每次读取计划都会同时校验 `LifePlan` 结构和 SHA-256 校验和。完整性校验失败的计划不会进入计算，可通过有效快照或 JSON 备份恢复。

首页到工作台使用 `sessionStorage` 中的临时交接包，版本为 `2.0.0`，有效期 30 分钟；只有成功持久化后才清除。旧版首页草稿和旧正式计划存在兼容迁移入口。

JSON 备份格式为 `1.0.0`。导入时先解析、校验并运行正式计算，全部通过后才替换当前计划；原计划和导入计划都会留下可恢复快照。

“清空本页项目”只删除当前规划模块中的对应项目；“删除并重新创建”会在确认后清除当前浏览器中的计划、快照和结果缓存。

### 11. 离线能力

生产构建生成带构建版本的 Service Worker，只缓存公开的首页、规划页以及所需静态资源，不缓存 API、账户信息或个人计划。

离线能力的边界为：

- 首次使用必须联网，让应用壳和静态资源准备完成。
- 完成准备后，可以断网重新打开首页和规划页、读取 IndexedDB 计划、编辑、计算和保存。
- 新版本不会强制刷新正在编辑的页面。
- 缓存保留当前和上一版本的公开静态资源，降低版本切换时 HTML 与脚本不匹配的风险。
- 浏览器不支持 Service Worker、禁用存储或用户清除网站数据时，离线启动和本地计划均不能保证。

### 12. 隐私与安全边界

- 首页和工作台的正式计算均在浏览器内完成。
- 财务和家庭数据不进入 URL、页面标题或分析事件。
- Service Worker 不缓存个人计划或带凭据的请求。
- 导出备份由用户主动下载；系统不自动上传。
- 本地保存不等于跨设备备份，清除浏览器网站数据可能删除计划，因此产品提供 JSON 导出和快照恢复。

### 13. 质量保障

当前自动化范围包含：

- 金额、月份、比例和数据解析单元测试。
- 月度公式、年度汇总、本金口径、投资展示区间、负余额成本和房贷计算测试。
- 黄金案例、不变量、随机输入和确定性测试。
- 职业变化、多人事件、购房、时间轴、阶段支出、固定规则、试算与撤销测试。
- 首页交接、IndexedDB、备份、快照、冲突和离线 Worker 测试。
- 中英文文案键一致性与正式流程不依赖 AI 的静态合同测试。
- 手机、平板和桌面浏览器流程、无水平溢出、键盘焦点和自动无障碍检查。

仓库当前计算测试为 148 项。自动测试和模拟视口检查不替代真实金融审计、真实读屏器、物理设备或用户研究。

## 四、产品原则总结

一生账本当前实现遵循以下原则：

1. **一个计划模型**：首页、规划、图表、试算和账本使用同一份正式数据。
2. **一个计算内核**：所有正式数字和比较结果由同一确定性月度计算器产生。
3. **不重复计算**：总额、明细和额外事件有明确替代关系。
4. **现金与资产分开**：可用资金、非流动资产、债务和净资产始终分开呈现。
5. **先看结论，再查依据**：主界面突出当前决策需要的信息，精确数据、公式记录和版本按需展开。
6. **用户确认后才改变计划**：表单提交、总额超限确认和试算应用都需要明确操作。
7. **本地优先**：计算与存储默认发生在当前浏览器，支持导出、恢复和准备后的离线使用。
8. **不制造确定性**：产品使用条件式文案，不把情景估算写成预测、承诺或建议。
