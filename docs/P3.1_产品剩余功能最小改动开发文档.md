# 一生账本产品剩余功能最小改动开发文档

## 1. 文档目标

本文定义在不重做现有产品、不改变“规划／分析”双页面结构的前提下，将一生账本补齐为可发布 MVP 所需的剩余开发工作。

本阶段只完成五项能力：

1. 在规划中增加投资安排，并在分析页用区间铺色展示潜在收益与亏损。
2. 在住房规划中增加可被用户发现的“换城市生活”入口。
3. 接通规划助手的解释能力。
4. 允许规划助手提出受控试算，但所有金额仍由本地确定性计算器产生。
5. 增加城市房价、租金等外部数据候选，用户确认后才能采用。

已有 Landing、规划表单、住房计算器、人生事件、年度快照、长期趋势、人生时间轴、资金流图和本地保存继续复用。独立“年度账本”页面不恢复。

## 2. 完成后的产品形态

### 2.1 Landing

Landing 继续收集最少基线信息，并通过“加入人生大事”进入规划页。不增加城市、投资风险或 Agent 输入，避免首屏负担。

### 2.2 规划页

规划页继续保持左侧编辑、右侧长期结果预览：

- 左侧增加一个清晰可见的“投资”阶段。
- “住房”中增加“换城市生活”快捷入口，不新增顶级“城市”阶段。
- 右侧仍默认展示长期趋势，并即时反映已确认的本金和现金流变化。
- 投资收益区间只出现在指定的投资情景图，不进入右侧其他正式结果。

### 2.3 分析页

分析页继续保持左侧完整报告、右侧规划助手：

- 原“三种简单情景”图改为“本金计划线 + 投资收益／亏损区间”。
- 删除“较顺利”和“有压力”两条固定情景线。
- 规划助手解释当前计划、投资区间和城市安排。
- 规划助手不能自行写入计划，修改必须经过试算、确认和撤销链路。

## 3. 最小改动原则

1. 不新增主页面、全局导航或独立聊天页面。
2. 不重写现有月度计算器；正式账本继续作为所有正式数字的唯一来源。
3. 投资收益是展示层情景，不进入正式账本、缺口判断、资金可持续年龄或净资产结论。
4. 换城市的费用继续复用现有收入／支出项目，不建立第二套现金流模型。
5. 外部城市数据只生成候选值，不直接写入计划。
6. Agent 只解释和组织操作，不能计算正式金额，也不能绕过确认。
7. 新字段均为可选字段，旧计划可直接读取；不要求用户重新建档。

## 5. 投资安排

### 5.1 产品定位

投资模块用于展示不确定收益对长期资金曲线可能造成的影响，不提供投资建议，不推荐具体产品，也不承诺收益。

正式结果采用本金口径。用户看到的“资金可持续至几岁”“首次缺口”“最低可用资金”“年末资金”和 Agent 正式结论，均不包含投资收益。

### 5.2 规划入口

在左侧阶段导航中增加“投资”，位置建议在“住房”之后、“退休”之前。移动端阶段下拉同步增加该选项。

投资页面支持多个投资安排。每项包含：

- 名称。
- 本金。
- 风险档位。
- 年化收益下限。
- 年化收益上限。
- 开始月份。
- 结束月份。

暂不增加每月定投、手续费、税费、分红、杠杆、锁定期、币种或具体金融产品。

### 5.3 风险档位

使用中性档位名称：

- 低波动。
- 中波动。
- 高波动。
- 自定义。

不使用“稳定”“保本”“安全”等容易形成保证含义的名称。

前三个档位只负责填入可编辑的收益上下限。建议初始模板为：

| 档位   | 年化下限 | 年化上限 |
| ------ | -------: | -------: |
| 低波动 |      -3% |       5% |
| 中波动 |     -10% |      15% |
| 高波动 |     -25% |      30% |

模板是界面便捷输入，不是市场预测。用户修改任一上下限后，档位显示为“自定义”。

### 5.4 数据结构

投资情景与正式资产分开保存。正式资产仍使用现有 `Asset`，投资情景作为可选元数据引用资产：

```ts
type InvestmentRiskLevel = 'low' | 'medium' | 'high' | 'custom';

interface InvestmentScenario {
  id: string;
  name: string;
  assetId: string;
  principalCents: MoneyCents;
  riskLevel: InvestmentRiskLevel;
  lowerAnnualReturnBps: BasisPoints;
  upperAnnualReturnBps: BasisPoints;
  startMonth: MonthIndex;
  endMonthExclusive: MonthIndex;
}
```

`LifePlan.metadata` 增加可选的 `investmentScenarios`。旧计划缺少该字段时按空数组处理。

每项情景必须关联一个 `kind: 'investment'` 的资产。该资产在正式账本中：

- `annualReturnBps` 固定为 0。
- 只按本金进入资产和可用资金。
- 不因为创建投资安排而新增一份资产。

同一资产在同一月份只能有一个生效中的投资情景，防止收益区间重复叠加。

### 5.5 正式计算规则

正式月度计算器保持确定性：

- `annualLiquidReturnBps` 在正式计算中固定按 0 处理。
- 投资资产的 `annualReturnBps` 在正式计算中固定按 0 处理。
- 资金缺口成本、房贷利息等真实负债成本继续计算。
- 投资本金仍可进入正式资产和净资产，但不产生收益或亏损。
- 投资开始和结束只是情景区间，不作为收入或支出。

现有“高级假设”中的“可用资金实际年收益率”从正式规划表单移除。旧计划中的非零值读取时保留原始数据，但正式结果不再应用，并在首次保存时归零。

### 5.6 投资区间计算

新增纯函数 `calculateInvestmentRange`，输入正式年度结果和投资情景，输出每年的下限、本金口径和上限。

规则：

1. 开始月份之前，投资收益差额为 0。
2. 生效期间，下限按年化收益下限折算月度复利，上限按年化收益上限折算月度复利。
3. 结束月份之后停止复利，结束时形成的收益或亏损差额保持不变。
4. 下限不得低于本金全部损失，即最低年化输入不得小于 -100%。
5. 上限先限制为 200%，避免误输入造成图表失真；未来如有专业模式再放宽。
6. 多项投资按每年收益差额相加，不把本金重复加入正式资金。

每个图表点：

```text
本金计划值 = 正式年度结果中的年末可用资金
区间下限 = 本金计划值 + 所有投资的下行情景收益差额
区间上限 = 本金计划值 + 所有投资的上行情景收益差额
```

### 5.7 图表调整

复用现有 `ScenarioChart` 卡片，不新建额外图表：

- 深色实线：本金计划。
- 本金线上方淡绿色铺色：潜在收益区间。
- 本金线下方淡橙色铺色：潜在亏损区间。
- 上下边界使用极淡描边或不显示，避免恢复成三条线。
- 删除“较顺利”和“有压力”的图例、计算和说明。
- Tooltip 显示年份、年龄、本金计划、区间下限和区间上限。
- 图下固定说明“仅展示投资情景范围；其他结果均按本金计算，不代表预测或承诺”。

没有投资安排时，图表只显示本金计划线，并提供“添加投资安排”的轻量入口。

## 6. 换城市生活

### 6.1 入口和可发现性

不新增顶级“城市”导航。在“住房”阶段顶部显示三个快捷入口：

- 租住与收租。
- 购房。
- 换城市生活。

“其他人生事件”的参考项目中也保留“换城市”，但点击后统一进入住房中的换城市编辑器。

### 6.2 最少输入

换城市安排包含：

- 当前城市，可选。
- 目标城市。
- 搬迁月份。
- 一次性搬迁费用，可选。
- 搬迁后的每月住房支出变化，可选。
- 搬迁后的每月生活支出变化，可选。
- 搬迁后的每月收入变化，可选。

所有金额都是“变化量”，不是要求用户重新填写完整收入和支出。收入或支出没有变化时填写 0。

### 6.3 数据复用

换城市本身保存为轻量事件，具体金额继续生成现有 `CashFlowItem`：

```ts
interface RelocationPlan {
  id: string;
  currentCity?: string;
  targetCity: string;
  moveMonth: MonthIndex;
  movingExpenseFlowId?: string;
  housingAdjustmentFlowId?: string;
  livingAdjustmentFlowId?: string;
  incomeAdjustmentFlowId?: string;
  source?: ValueSource;
}
```

`LifePlan.metadata` 增加可选的 `relocations`。各金额分别映射为：

- 搬迁费用：一次性 `other` 或 `housing` 支出。
- 住房变化：从搬迁月开始的 `housing` 月度收入或支出。
- 生活变化：从搬迁月开始的 `living` 月度收入或支出。
- 收入变化：从搬迁月开始的独立收入调整，不覆盖职业工资轨迹。

删除换城市安排时，只删除该安排引用的现金流，不影响用户手工创建的其他项目。

### 6.4 时间轴和报告

确认后，人生时间轴增加城市节点：

```text
35 岁 · 搬到杭州
```

节点点击后返回住房中的对应安排。长期趋势在该年龄显示竖向事件标记。年度快照和资金流图自然读取已生成的正式现金流，不增加专用计算逻辑。

### 6.5 无数据 API 时的文案

第一版城市名称只是计划标签，不自动推断费用。编辑器固定显示：

> 城市用于标记人生安排，费用暂由你确认。

这保证换城市功能可以先发布，不依赖外部数据服务。

## 7. 规划助手解释模式

### 7.1 UI 复用

继续使用分析页右侧现有 `AgentPanel`：

- 移除“即将上线”状态。
- 启用输入框和发送按钮。
- 示例问题可以直接填入输入框。
- 回答区在面板内部滚动，不改变左右栏布局。
- 移动端使用同一组件顺序展示，不新增 Drawer。

### 7.2 最小上下文

每次请求只发送：

- 当前计划摘要。
- 用户正在查看的年份和年龄。
- 首次缺口、最低资金、终点资金。
- 已添加的人生事件、投资情景和换城市安排摘要。
- 当前页面可见图表的结构化数值。
- 允许解释的字段和允许试算的动作列表。

不发送完整月度流水、用户未填写的数据或浏览器中的其他内容。

### 7.3 API

新增专用服务端接口 `POST /api/life-ledger/agent`。复用项目已有 AI SDK 和模型提供方配置，不改造通用 Chat 页面。

请求：

```ts
interface AgentRequest {
  question: string;
  context: LifeLedgerAgentContext;
  mode: 'explain' | 'propose';
}
```

解释模式只返回流式文本和引用的上下文字段，不返回可执行 patch。

### 7.4 隐私与降级

- 第一次发送前说明哪些账本摘要会离开浏览器，并要求确认。
- 用户拒绝后仍可完整使用所有手动功能。
- API 未配置、超时或限流时显示可重试错误，不清空问题和历史回答。
- 不在日志中记录完整计划和用户问题正文。
- Agent 回答必须明确区分“正式本金结果”和“投资展示区间”。

## 8. 规划助手受控试算

### 8.1 首批允许动作

只开放现有计算器能可靠处理的白名单动作：

- 调整退休时间。
- 调整退休月支出。
- 调整住房支出或搬迁时间。
- 调整起始可用资产。
- 调整投资本金、收益上下限或生效时间。

投资试算只改变投资区间图；除本金变化外，不改变正式结论。

### 8.2 执行链路

```text
Agent 提出结构化草案
  → Zod 校验动作和目标 ID
  → 本地复制计划
  → 正式计算器或投资区间函数重算
  → 展示修改前后数字与图表
  → 用户确认
  → 写入正式计划
  → 提供一次撤销
```

Agent 不得直接调用计划更新函数。自然语言中的数字不得直接作为正式结果展示，必须先经过本地重算。

### 8.3 比较结果

正式计划修改展示：

- 首次缺口。
- 最低可用资金。
- 终点可用资金。
- 受影响的人生事件和年份。

投资情景修改展示：

- 本金计划保持不变或本金变化。
- 原区间下限／上限。
- 新区间下限／上限。
- 收益区间不进入正式结论的提示。

## 9. 城市数据 Agent

### 9.1 数据范围

第一版只查询：

- 城市租金参考。
- 城市住宅单价参考。

生活成本和工资数据来源不稳定，先不作为自动候选；用户仍可手工填写变化量。

### 9.2 返回结构

```ts
interface CityDataCandidate {
  city: string;
  metric: 'rent' | 'home_price';
  value?: number;
  lower?: number;
  upper?: number;
  unit: string;
  sourceName: string;
  sourceUrl: string;
  region: string;
  effectiveMonth?: MonthIndex;
  retrievedAt: string;
}
```

候选卡必须同时展示来源、地区、数据日期、单位和口径。缺少其中任一项时不允许出现“采用”按钮。

### 9.3 写入规则

- 查询不会改变计划。
- 用户点击“采用此金额”后，候选值进入换城市或住房表单的草稿。
- 用户再次确认保存后才生成正式现金流。
- 保存 `ValueSource.kind = 'external'` 和完整来源信息。
- 外部数据更新不会自动覆盖用户已经确认的金额。

如果没有合适 API，城市功能继续使用手工输入，不阻塞 MVP 发布。

## 11. 开发阶段

### 阶段一：本金口径收敛（已完成）

- 正式资产收益率固定为 0。
- 移除高级假设中的正收益输入。
- 更新公式说明和回归测试。

放行条件：关闭投资情景时，所有正式数字与本金口径一致，收益为 0。

完成结果：正式计算忽略旧计划中的正余额和非流动资产收益率；高级假设只保留资金缺口成本；任何已接受的编辑会把旧收益字段归零。相关计算、旧数据兼容和本金口径测试已通过。

### 阶段二：投资安排和区间图（已完成）

- 投资数据结构、编辑器和校验。
- 三线图替换为本金线和区间铺色。
- 多投资、起止月份和空状态。

放行条件：投资配置只能改变区间图，不能改变正式缺口和资金结论。

完成结果：规划导航已增加投资模块，支持多项投资、四档风险、可编辑上下限和起止月份；正式本金在现金与投资资产之间转移，不增加总资产；分析页原三线图已替换为本金线和收益／亏损铺色区间。长期资金图同时移除了退休竖线，并把重叠的人生事件改为图内轻量节点加图下清晰列表。

### 阶段三：换城市生活（已完成）

- 住房快捷入口和编辑器。
- 复用现金流生成费用变化。
- 时间轴节点和返回编辑联动。

放行条件：换城市产生的每笔正式金额都能追溯到现有年度账本。

完成结果：住房模块已增加“换城市生活”入口和多安排编辑器，支持记录当前城市、目标城市、搬迁月份、一次性搬迁费，以及搬迁后的住房、生活和收入月度变化。用户确认的金额统一转换为现有正式现金流；只记录城市但不填写金额时不改变任何计算。人生时间轴和长期趋势会显示搬迁节点，点击后可返回对应安排。阶段三不依赖城市 API，也不会根据城市名称自动生成金额。

## 12. 测试要求

### 12.1 投资

- 正式结果不含任何投资收益。
- 风险模板切换和自定义值正确保存。
- 下限不高于上限，时间范围合法。
- -100% 下限不会产生负投资价值。
- 多投资区间正确合并且本金不重复。
- 开始前无区间，结束后停止复利。
- 删除投资后本金资产不会被误删。

### 12.2 换城市

- 仅城市名称不会改变计算结果。
- 每项费用变化只生成一次现金流。
- 修改不会重复追加，删除只清理关联项。
- 城市节点按时间排序并可返回编辑器。
- 外部候选未经确认不会写入计划。

### 12.3 Agent

- 解释模式不能返回可执行修改。
- 试算失败不会改变正式计划。
- 非白名单动作被拒绝。
- 过期 revision 的试算不能应用。
- 确认后可撤销一次。
- API 失败不影响手动规划、保存和导出。

### 12.4 E2E 主路径

```text
Landing 建立基线
  → 添加投资本金和收益区间
  → 图表只出现本金线与区间铺色
  → 添加换城市及费用变化
  → 时间轴出现城市节点
  → Agent 解释当前计划
  → Agent 提出试算
  → 查看差异并拒绝或确认
  → 刷新后计划保持一致
```

## 13. 最终验收标准

- 产品仍只有“规划”和“分析”两个主页面。
- Landing 仍可直接进入规划页。
- 投资收益只出现在投资区间图，其他正式结果只按本金计算。
- 固定“较顺利／有压力”情景已完全删除。
- 用户能在住房模块明显发现“换城市生活”。
- 没有城市 API 时仍可完整记录换城市计划。
- Agent 能解释计划，但不能自行制造或修改正式金额。
- Agent 的任何修改都经过结构化校验、本地重算和用户确认。
- 外部城市数据带来源和日期，未经确认不写入计划。
- 旧计划、手动编辑、本地保存、备份恢复和无网络使用不受影响。

## 14. 明确不做

以下能力不属于本轮“完整 MVP”：

- 证券交易、基金购买或真实账户连接。
- 个性化投资建议、资产配置建议或具体产品推荐。
- Monte Carlo 概率模拟和成功率承诺。
- 银行流水自动同步。
- 完整个税、保险、遗产和养老金自动测算。
- 多币种和海外税务。
- 自动根据城市名称修改全部工资和生活成本。
- 多 Agent 导航、模型选择器、聊天积分或独立聊天历史页面。
- 云端多人协作和家庭共享账户。

这些能力以后可以扩展，但不应阻塞当前产品完成和发布。
