# 一生账本：产品开发与页面设计说明

> 版本：v2.0  
> 更新日期：2026-10-13  
> 状态：产品、计算、Agent 与界面开发基线  
> 项目：shipany-template-two-dev

## 1. 产品目标

一生账本是一款家庭长期收支规划计算器，帮助用户回答：

1. 按照当前计划，一生是否会出现资金缺口？
2. 缺口最早什么时候出现，主要由什么造成？
3. 为维持目标生活，家庭需要多少收入？
4. 改变住房、家庭或退休计划后，结果如何变化？

核心原则：

- 计算器负责结果，Agent 负责理解、填写和解释。
- 先定义数据，再验证计算，最后扩展功能。
- 同一笔收入或支出只能计算一次。
- 总额可以逐步拆分，详细数据替代概括数据，不与其叠加。
- 用户输入、系统估算、外部数据和计算结果必须可区分、可追溯。
- 页面只展示当前决策需要的信息，其他内容按需展开。

开发主线：

```text
数据标准 → 准确计算 → 最小产品 → 规划 Agent → 数据 Agent
→ 完整人生模块 → 决策增强 → 账户与商业化
```

## 2. 产品边界

### 2.1 第一版解决的问题

- 建立一份本地家庭计划。
- 计算长期可用资金变化。
- 找到首次资金缺口和最低余额。
- 反算维持目标生活所需收入。
- 修改计划并立即看到结果变化。
- 通过自然语言填写和理解计划。

### 2.2 第一版不解决的问题

- 不提供投资建议或未来保证。
- 不模拟完整个税，收入填写税后金额。
- 不允许 AI 自行生成最终资金结果。
- 不自动发布 Agent 获取的房价或政策数据。
- 不开发登录、支付、订阅、社交和多人协作。
- 不把房产价值与可用现金混为一谈。

### 2.3 金额口径

- 默认货币为人民币。
- 默认按今天的购买力计算。
- 内部按月计算，页面按年汇总。
- 必须区分可用资金、债务余额和净资产。
- 所有金额明确标注每月、每年或一次性。
- 所有结论使用“按照当前输入，预计……”等条件式表达。

## 3. 唯一数据标准

页面、计算器、两个 Agent 和导出功能必须使用同一套数据定义，不得各自维护字段。

### 3.1 计划数据

一份计划由以下内容组成：

- 基本情况：年龄、城市、规划终点。
- 家庭成员：自己、伴侣、孩子、父母。
- 收入：工资、副业、养老金、一次性收入。
- 支出：住房、生活、孩子、父母、退休、其他事件。
- 资产：现金、存款、投资、房产。
- 债务：房贷及其他负债。
- 假设：通胀、收入变化、收益和外部参考数据。
- 元数据：创建时间、更新时间、计算版本和数据版本。

每笔收入或支出至少记录：

| 字段 | 含义                                      |
| ---- | ----------------------------------------- |
| 金额 | 使用精确金额存储，避免浮点累计误差        |
| 频率 | 每月、每年或一次性                        |
| 分类 | 收入、住房、生活、孩子、父母、退休等      |
| 归属 | 自己、伴侣、孩子、父母或全家              |
| 时间 | 开始与结束月份                            |
| 来源 | 用户填写、系统估算、外部参考或 Agent 建议 |
| 状态 | 概括金额、详细金额、待确认或已确认        |
| 版本 | 使用的数据和计算版本                      |

### 3.2 总额与分类

首页允许用户只填写总额，例如每月支出 7,000 元。进入正式计划后逐步拆分：

| 分类     |     金额 |
| -------- | -------: |
| 住房     | 2,000 元 |
| 家庭生活 | 2,000 元 |
| 孩子     | 2,000 元 |
| 父母     | 1,000 元 |
| 待分类   |     0 元 |
| 合计     | 7,000 元 |

规则：

- 详细分类替代总额中的对应部分，不能额外叠加。
- 分类不足时，差额保留为“待分类”或“其他”。
- 分类超过原总额时，必须由用户确认新的总额。
- 从概括模式切换到详细模式后，概括金额停止参与计算。
- 住房、孩子、父母等模块均使用同一替代规则。
- 收入总额和收入明细遵循相同规则。

### 3.3 数据来源

| 来源       | 使用规则                       |
| ---------- | ------------------------------ |
| 用户填写   | 优先使用，修改后立即重算       |
| 系统估算   | 明确标记，可被用户覆盖         |
| 外部参考   | 显示来源、地区、日期和统计口径 |
| Agent 建议 | 应用前必须预览并确认           |
| 计算结果   | 只能由确定性计算器生成         |

任何会明显改变结果的默认值都不得隐藏。

## 4. 计算准确性

### 4.1 计算核心

- 将原有 model.js 重构为独立 TypeScript 模块。
- 不依赖页面、React、浏览器存储或 AI。
- 输入不可变；相同输入与版本必须产生相同结果。
- 内部按月推进，输出逐月记录与逐年汇总。
- 结果包含输入摘要、计算版本和数据版本。
- 失败时返回结构化错误，不返回看似正常的部分结果。

### 4.2 核心结果

- 规划期内是否出现资金缺口。
- 首次资金缺口月份和年份。
- 最低可用资金。
- 规划终点可用资金。
- 退休时可用资金。
- 所需家庭月收入。
- 可用资金、债务和净资产曲线。
- 收入与支出分类汇总。
- 对结果影响最大的三项参数。

必须分别判断：

- 规划终点是否仍有结余。
- 中间月份是否始终没有出现负数。

### 4.3 测试体系

| 测试         | 目的                       |
| ------------ | -------------------------- |
| 公式单元测试 | 验证每条计算规则           |
| 人工黄金案例 | 使用可手算案例确认结果     |
| 回归测试     | 防止旧功能被意外改变       |
| 不变量测试   | 保证总额守恒、无重复计算   |
| 随机测试     | 发现边界输入和组合问题     |
| 数据校验     | 检查单位、日期、地区和来源 |

首批黄金案例至少覆盖：

- 单身租房。
- 已有住房。
- 房贷还款。
- 伴侣收入。
- 孩子支出。
- 父母赡养。
- 提前退休。
- 工作中断。
- 一次性大额支出。
- 最终有结余但中途缺钱。

### 4.4 计算放行条件

以下条件全部满足后，才能开发依赖结果的正式页面：

- 总额与明细不会重复计算。
- 黄金案例由人工核对通过。
- 所有失败输入均可复现。
- 计算结果可追溯到输入和公式。
- 金额单位、时间单位和购买力口径一致。
- 页面、测试和发布版本使用同一默认参数。

## 5. 两个 Agent

### 5.1 规划 Agent

面向用户，嵌入计划工作台，不设置独立聊天页面。

能力：

- 将自然语言转换为候选参数。
- 帮助拆分收入和支出总额。
- 发现遗漏、冲突和可能的重复计算。
- 解释缺口原因和主要影响因素。
- 创建临时方案并调用计算器比较。

流程：

```text
理解请求 → 生成修改草稿 → 校验 → 展示差异
→ 用户确认 → 写入计划 → 调用计算器
```

约束：

- 不直接计算金额结果。
- 不在未确认时修改金额、家庭、住房和退休字段。
- 不覆盖主计划；试算使用临时方案。
- 不确定内容必须提问或标记为待确认。
- AI 失败时不影响手动填写和计算。

规划 Agent 只调用以下受控工具：

- 读取当前计划。
- 生成计划修改草稿。
- 校验草稿。
- 应用已确认修改。
- 运行确定性计算。
- 创建并比较临时方案。
- 查询参数来源。

### 5.2 数据 Agent

内部使用，不进入普通用户导航。

首批关注：

- 城市生活成本。
- 房价参考区间。
- 房贷参考利率。
- 首付比例。
- 养老金相关参考数据。

流程：

```text
检查可信来源 → 提取变化 → 与当前版本比较
→ 附上证据和生效日期 → 人工审核 → 发布新数据版本
```

每项建议必须包含：

- 地区与指标。
- 原值与建议值。
- 单位和统计口径。
- 来源链接、发布日期和生效日期。
- 变化原因。
- 可信程度。
- 审核状态。

约束：

- 只读取允许清单中的可信来源。
- 政策优先使用政府或官方原始文件。
- 不自动发布正式数据。
- 不自动修改计算公式。
- 数值变化可以进入数据审核；规则变化必须进入开发审核和测试。
- 房价默认作为参考区间，不覆盖用户输入。

早期不开发数据后台。Agent 生成结构化更新建议文件，由人工审核后发布。

## 6. 最小信息架构

普通用户只看到两个页面：

| 页面         | 路由  | 职责                             |
| ------------ | ----- | -------------------------------- |
| Landing Page | /     | 解释产品、快速估算、进入正式计划 |
| 计划工作台   | /plan | 创建、编辑、查看、对比和核对计划 |

计划工作台只有两个主视图：

| 视图 | 职责                                                       |
| ---- | ---------------------------------------------------------- |
| 概览 | 结论、核心指标、曲线、主要影响因素，以及按需展开的逐年账本 |
| 计划 | 输入、拆分、修改和完整性检查                               |

不再设置独立用户页面：

- 创建计划：无计划时，工作台自动进入创建状态。
- 方案对比：在概览内切换对比模式。
- 假设与依据：从数字、字段或图表打开依据抽屉。
- 计算说明：在依据抽屉内按需展开。
- Agent：桌面端侧栏，移动端全屏面板。
- 导出和数据管理：放入更多菜单。

安全的界面状态可以进入 URL：

```text
/plan?tab=overview
/plan?tab=plan&section=housing
```

收入、存款、家庭情况等数据不得进入 URL、标题或分析事件。

## 7. 页面设计

### 7.1 Landing Page

页面顺序：

1. Hero：主标题、副标题、快速计算器。
2. 快速结果：一个结论、三个关键数字。
3. 三步说明：填写、计算、调整。
4. 可信说明：计算口径、数据来源、隐私边界。
5. 简洁页脚：隐私政策、服务条款、语言和主题。

快速计算器保留两个入口：

- 按现在收入看结果：根据当前收入判断退休资金结余或缺口。
- 按目标生活算收入：根据工作期与退休期开销反算所需月收入。

基础字段包括：

- 当前年龄。
- 退休年龄。
- 规划终点年龄。
- 税后月收入（仅“按现在收入”模式填写）。
- 工作期每月开销。
- 退休后每月需自付。
- 当前存款。

结果必须标记：

> 这是基于总额的快速估算。拆分住房、孩子和父母支出后，结果会更准确。

主操作：完善我的一生账本。  
次操作：重新估算。

点击主操作后：

1. 将快速输入临时保存到 sessionStorage。
2. 进入 /plan。
3. 创建本地草稿并读取数据。
4. 成功读取后清除临时数据。

首页不展示定价、登录、博客、通用 AI 或脚手架产品入口。

### 7.2 计划工作台

### 全局结构

顶部栏只显示：

- 一生账本。
- 计划名称。
- 保存状态。
- “按今天的钱计算”。
- 规划 Agent。
- 更多菜单。

桌面端使用顶部标签：概览、计划。  
移动端使用底部导航：概览、计划。

不设置常驻侧栏。规划 Agent 打开时使用右侧面板。

### 概览

首屏顺序：

1. 一句话结论。
2. 四个核心指标。
3. 一张主要资金曲线。
4. 三个主要影响因素。
5. 数据完整性提示。
6. 修改计划与比较变化。
7. 可折叠的逐年账本。

四个核心指标：

- 是否出现资金中断。
- 首次缺口时间。
- 最低可用资金。
- 所需家庭月收入。

终点结余与中途是否缺钱必须同时表达，但不重复制作两组结果卡。

数据完整性只使用三级文字：

- 基础估算。
- 已补充主要信息。
- 详细计划。

不使用无法证明的“准确率百分比”。

对比模式在本视图内完成：

- 基准方案与一个临时方案并排。
- 只显示发生变化的参数和结果。
- 可以采用新方案，也可以丢弃。
- 不静默覆盖主计划。

### 计划

顶部固定摘要：

- 月收入。
- 月总支出。
- 已分类金额。
- 待分类金额。
- 当前可用资金。

下面使用单层折叠分组，一次只展开一个：

1. 基本情况。
2. 收入与工作。
3. 日常生活。
4. 住房。
5. 家庭与孩子。
6. 父母。
7. 退休。
8. 人生事件。
9. 高级设定。

每个折叠项只显示：

- 分类名称。
- 当前概括金额。
- 数据来源。
- 是否需要补充。
- 展开与修改入口。

交互规则：

- 概括模式和详细模式只能启用一个。
- 有效输入停止 300～500ms 后重算，或失焦后重算。
- 输入未完成时保留上一次有效结果，并显示“结果待更新”。
- 重大变化展示简短差异，不在每次按键后跳动。
- 系统估算和 Agent 建议必须带标记。
- 高级参数默认折叠。

### 概览中的逐年账本

账本不作为一级导航，默认折叠在概览底部。展开后显示：

默认显示：

- 年份范围。
- 资金曲线或分类构成切换。
- 逐年明细表。
- 首次缺口定位。

点击某一年打开年度详情抽屉，内容包括：

- 收入。
- 生活支出。
- 住房。
- 孩子。
- 父母。
- 退休与养老金。
- 一次性事件。
- 债务变化。
- 年末可用资金和净资产。

图表和表格不重复承担同一职责：

- 图表用于看趋势。
- 表格用于查精确数字。
- 抽屉用于解释某一年。

图表最多同时显示三条曲线，并提供表格替代。

### 依据抽屉

点击任意数字旁的来源标记打开，统一展示：

- 当前值。
- 用户输入或估算来源。
- 数据日期和地区。
- 是否影响结果。
- 修改入口。
- 外部参考链接。
- 计算版本和数据版本。
- 必要时展开计算说明。

依据只在一个地方展示，概览、计划和账本通过同一个抽屉调用。

### 规划 Agent 面板

根据当前视图提供建议：

- 帮我拆分每月支出。
- 检查有没有重复计算。
- 为什么这一年出现缺口？
- 比较 55 岁和 60 岁退休。
- 哪些信息最值得补充？

所有修改先显示差异清单，再由用户确认。

## 8. 本地数据

| 存储           | 用途                           |
| -------------- | ------------------------------ |
| sessionStorage | 首页到工作台的临时交接         |
| IndexedDB      | 正式计划、草稿、方案和版本信息 |
| localStorage   | 语言、主题等轻量偏好           |

规则：

- 第一版只支持一个本地计划，但数据仍使用随机 ID。
- 输入是唯一事实来源，结果由输入实时生成。
- 结果缓存必须绑定输入哈希、计算版本和数据版本。
- 自动保存采用防抖和原子更新。
- 多标签页冲突时提示用户，不静默覆盖。
- 数据损坏时允许导入备份、恢复最近快照或重新创建。
- 浏览器本地数据不宣称已加密或绝对安全。

保存状态统一为：

- 保存中。
- 已自动保存。
- 保存失败。
- 结果待更新。
- 当前显示上一次有效结果。

## 9. 开发优先级

### P0：数据标准

完成：

- 统一计划数据结构。
- 总额与分类替代规则。
- 时间、金额、来源和版本标准。
- 数据校验和迁移方案。
- 黄金案例输入与预期结果。

放行条件：任何收入或支出都不会重复计算。

### P1：准确计算

完成：

- TypeScript 月度计算核心。
- 年度汇总和核心结果。
- 公式、黄金、回归、不变量和随机测试。
- 可用资金、债务和净资产分离。
- 计算与数据版本。

放行条件：人工案例、自动测试和边界测试全部通过。

### P2：最小可用产品

详细开发设计见：[P2 最小可用产品开发设计说明](./P2_最小可用产品开发设计说明.md)。

完成：

- Landing Page 快速估算。
- 计划工作台的创建状态。
- 概览、计划两个主视图；逐年账本在概览内按需展开。
- 本地保存、备份恢复和移动端适配。
- 首页总额进入工作台后可以正确拆分。

放行条件：不使用 AI 也能创建、理解、修改并核对一份计划。

### P3：规划 Agent

完成：

- 自然语言填表。
- 修改预览和确认。
- 结果解释。
- 临时方案对比。

## 10. 视觉与内容规范

目标：简洁、安静、可信，像一本可以核对的现代账本。

### 10.1 视觉

- 浅米白或浅灰背景，白色内容表面，深墨色正文。
- 翡翠绿只用于主要操作、选中和正常状态。
- 琥珀色用于估算、待确认和数据过期。
- 红色只用于错误和危险操作。
- 一套无衬线字体，金额使用等宽数字。
- 使用留白、字号和分隔线建立层级。
- 不嵌套卡片，不为普通分组添加阴影。
- 每个视图只有一个主要操作。
- 动效仅用于保存、重算、抽屉和状态变化，时长 150～250ms。

### 10.2 内容

- 一个结论只出现一次。
- 标题不重复正文。
- 按钮使用动作语言，如“完善计划”“比较变化”。
- 先给结论，再给依据。
- 专业术语提供解释，不堆叠免责声明。
- 金额默认使用万元或千元便于扫描，展开后显示精确值。
- 好坏状态不能只依赖红绿颜色，必须配合文字和图标。

### 10.3 响应式与可访问性

- 移动端不出现页面级横向滚动。
- 固定底栏避开系统安全区域和软键盘。
- 键盘可以完成填写、编辑、对比和导出。
- 输入有标签、说明和关联错误。
- 抽屉关闭后焦点返回触发位置。
- 图表提供表格替代。
- 页面缩放至 200% 时核心流程仍可使用。
- 中文优先完整交付；英文保留基础设施，正式开放前单独验收。

## 11. 隐私与可靠性

- 默认数据只保存在当前浏览器，不描述为“绝对安全”。
- 调用 AI 前说明发送字段和服务方。
- 只向规划 Agent 发送完成当前任务所需的数据。
- 分析事件不得包含收入、存款、年龄和家庭原始值。
- 导出文件提示包含敏感财务信息。
- 计算失败时保留上一次有效结果并明确提示。
- 数据或计算版本变化后，不静默改变旧结果。
- 用户主动选择后才使用新版本重新计算。
- 删除、清空和采用新基准方案必须二次确认。
