# 城市选择与迁居试算

## 目标

先区分用户是在做人生价值选择、城市成本比较，还是已经要执行迁居试算。成本数据只能支持财务维度，不能替用户决定职业、家庭和生活偏好。

## 输入

- 两座城市及其方向；
- 家庭人数和住房方式；
- 用户明确的决策标准；
- 当前计划中的迁居事项；
- MCP 返回的来源、版本、观察时间和有效期。

## 可用工具

- `lookup_city_costs`
- `simulate_relocation_candidate`

## 执行流程

1. 识别 `city_choice`、`city_cost_comparison` 或 `relocation_simulation`。
2. 城市选择缺少评价标准时，询问用户先比较财务影响还是补充职业、家庭和生活偏好排序。
3. 成本比较通过只读 MCP 查询；不把演示数据说成实时市场事实。
4. 检查候选城市是否与已有迁居事项一致。
5. 一致时在计划副本中试算；不一致时停止并澄清。
6. 展示来源、字段差异和财务结果，等待用户确认。

## 停止与异常

- 城市缺失或方向不清：追问城市，不猜测。
- MCP 超时、无数据或 Schema 错误：不使用旧值或猜测值继续试算。
- 用户询问“应该住哪里”：不直接推荐，先收集评价标准。
- 用户要求最新数据但只有演示源：明确拒绝实时结论。

## 验收

- “上海还是北京”被识别为城市选择而不是闲聊；
- MCP 候选包含来源与免责声明；
- 候选与迁居事项城市匹配；
- 正式计划在确认前不变。
