# 人生事件与方案试算

## 目标

把用户明确的调整目标转换成可校验的计划补丁，在正式计划副本上计算前后差异。候选方案不是已完成修改。

## 输入

- 结构化目标、对象 ID、调整值、时间和约束；
- 当前 `planHash` 与可编辑对象白名单；
- 当前计算结果。

## 可用工具

- `compare_retirement_ages`
- `compare_child_timing`
- `simulate_patch`
- `simulate_scenario`

## 执行流程

1. 定位唯一对象，校验调整幅度、单位和时间范围。
2. 对简单比较使用专用比较工具；对修改使用一个 `PlanPatch`。
3. 只有 2–3 个相互关联且参数完整的变化才组成组合试算。
4. 在副本上计算，核验 baseline hash 未改变且 candidate hash 已变化。
5. 展示字段差异和关键结果，进入待确认状态。
6. 用户确认时重新核对计划版本；版本变化则使候选失效。

## 停止与异常

- 对象或调整值缺失：只追问一个阻塞字段。
- 用户要求跳过确认：拒绝写入，但可以继续生成候选。
- 计算失败：丢弃候选，保持正式计划不变。
- 写入结果未知：先核对计划版本和保存状态，不直接重放。

## 验收

- 试算绑定正确的 `planHash`；
- 正式计划在确认前不变；
- 候选展示可理解的前后差异；
- 重复请求不会重复写入。
